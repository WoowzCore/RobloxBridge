# RobloxBridge

Десктопное приложение и плагин Roblox Studio для синхронизации плейса с локальной папкой. Сцена, скрипты и настройки сервисов хранятся в текстовом формате `.bridge`, который удобно смотреть в diff (Rider, git) и править вручную или с помощью ИИ.

Идея похожа на Rojo, но синхронизация **ручная**: кнопки **Pull** и **Push**, и перед любым применением показывается, что именно изменится.

- **Pull** (синяя кнопка): Studio → файлы.
- **Push** (зелёная кнопка): файлы → Studio.
- Перед применением всегда diff: что создастся, изменится, удалится, будет проигнорировано.
- После применения можно нажать **«↩ Отменить»**.
- Git не используется приложением: коммитит и пушит пользователь.

## Возможности

- Сцена: объекты, свойства, атрибуты, теги, ссылки между объектами, скрипты (`.luau` или `.lua`, короткие прямо в `.bridge`).
- Настройки сервисов (Workspace, Lighting, StarterPlayer и др.).
- Типы: Color3, CFrame, UDim2, Enum, ColorSequence/NumberSequence, FontFace, BrickColor, Faces, Axes, PhysicalProperties и др.
- Префабы: шаблоны с параметрами `${Имя}` (в свойствах и в коде скриптов).
- Юнионы (UnionOperation, NegateOperation, IntersectOperation): форма хранится в бинарных файлах по хешу.
- Террейн: воксели в одном бинарном файле на плейс, кнопки в приложении и в плагине.
- Защита от удаления: при Push из плагина запрос подтверждения, если удаляется много объектов.
- Несколько плейсов одной игры в одном проекте.

## Как это работает

```
┌──────────────────────────┐  HTTP, localhost:4949   ┌─────────────────────────┐
│ Плагин Roblox Studio     │ ──────────────────────▶ │ Приложение (C#)         │
│ (один .lua файл)         │ ◀────── ответ на ping ─ │ HttpListener + WebView2 │
└──────────────────────────┘                         └───────────┬─────────────┘
                                                                 │
                                                       файлы проекта на диске
```

- Приложение — сервер на `HttpListener`. Оно хранит файлы, читает и пишет формат `.bridge`, раздаёт схему классов. Интерфейс — WebView2 внутри GLFW-окна.
- Плагин — клиент. Он собирает сцену из Studio, отправляет её в JSON, получает операции и применяет их.
- Приложение не может обратиться к плагину напрямую: плагин раз в ~3 секунды опрашивает сервер, и команды приложения (Pull/Push/Применить/Отменить, в том числе для террейна) приходят в ответе на этот опрос. Поэтому кнопка в приложении срабатывает с задержкой до нескольких секунд.
- Плагин ничего не знает о формате `.bridge`. Разбор, запись, раскладка по файлам и проверка — в приложении.
- Схема классов и свойств строится из [Full-API-Dump.json](https://github.com/MaximumADHD/Roblox-Client-Tracker/blob/roblox/Full-API-Dump.json). Без дампа работа заблокирована (приложение подскажет и откроет страницу).

## Требования

- Windows (WebView2 Runtime).
- .NET 8 SDK (`net8.0`, без `-windows`).
- Roblox Studio.
- Собственные библиотеки проекта: [WoowzLib](https://github.com/WoowzCore/WoowzLib).
- Запускать Studio и приложение **без прав администратора**.

## Установка

1. Собери и запусти приложение (Rider: Run).
2. Установи плагин: положи `.lua` файл плагина в `%LOCALAPPDATA%\Roblox\Plugins\` и **полностью перезапусти Studio** (простая замена файла без перезапуска не подхватывается).
3. При первом запросе плагина Studio спросит разрешение на доступ к `localhost`: разреши.
4. В приложении загрузи дамп API (панель «API-дамп»).

### Сборка exe для другого компьютера

`dotnet publish -c Release` → папка `bin\Release\net8.0\win-x64\publish\`. Отдавай **всю папку** (zip), а не один exe: нативные библиотеки (`glfw3.dll` и др.) должны лежать рядом с exe. Опцию `IncludeNativeLibrariesForSelfExtract` не включай, иначе GLFW не загрузится. Установленный .NET не нужен, нужен WebView2 Runtime. Плагин `.lua` в сборку не входит, его ставят отдельно. Windows SmartScreen или антивирус могут ругаться на неподписанный exe.

## Быстрый старт

1. Открой плейс в Studio. У плейса должен быть PlaceId: если он 0, сделай File → Publish to Roblox.
2. Когда плагин найдёт приложение, в нём появится интерфейс. Создай проект кнопкой в плагине (проект создаётся только из плагина).
3. В приложении «Открыть проект» нужна, если проект уже существует. Последний проект открывается автоматически.
4. **Pull**: сцена и скрипты записываются в папку проекта.
5. Правь файлы в Rider или через ИИ.
6. Закоммить изменения в git, потом **Push**: проверь diff и подтверди (или включи «Применять сразу после проверки»).
7. Что-то пошло не так: **«↩ Отменить»** (откатывается только ближайшее применение).

Второй плейс той же игры добавляется кнопкой «Добавить этот плейс в проект».

## Структура проекта

```
MyGame/
  bridge.json              { "Format":1, "Name", "UniverseId", "Places": { "<PlaceId>": "<папка>" } }
  AGENTS.md                инструкция для ИИ (один на проект)
  Prefabs/*.bridge         общие префабы
  Places/<папка>/          по умолчанию папка = PlaceId
    place.json             PlaceId, Services, Ignore, Splits, AutoSplit, ScriptExt, InlineLines
    Scene/<Сервис>.bridge  по файлу на сервис
    Scene/<путь>.bridge    вынесенные поддеревья
    Scripts/<путь>.luau    тексты длинных скриптов
    Geometry/<хеш>.bin     формы юнионов
    Terrain.voxels         воксели (бинарный)
    _map.txt               обзор дерева (генерируется)
```

Машинные настройки (порт, последний проект) лежат в `robloxbridge.settings.json` рядом с exe, в проект они не попадают. Кэш схемы: `cache/schema.json`.

Файл `AGENTS.md` создаётся вместе с проектом. Если он удалён, его можно создать заново кнопкой «Создать AGENTS.md» в приложении.

### Что сохранять: `place.json`

- `Services`: какие сервисы синхронизируются. По умолчанию 12: Workspace, Lighting, MaterialService, ReplicatedFirst, ReplicatedStorage, ServerScriptService, ServerStorage, StarterGui, StarterPack, StarterPlayer, Teams, SoundService.
- `Ignore`: пути, которые синхронизация не видит (по умолчанию `Workspace/Camera`).
- `Splits`: поддеревья, вынесенные в отдельные файлы. Поддерево больше `AutoSplit` строк (по умолчанию 500, `0` = выключить) выносится само. Выносить и возвращать можно вручную из плагина.
- `ScriptExt`: расширение **новых** файлов скриптов, `luau` (по умолчанию) или `lua`. Существующие файлы не переименовываются и не теряются.
- `InlineLines`: новые скрипты не длиннее этого числа строк (по умолчанию 8, и не больше 400 символов) остаются кодом в `.bridge` (`@code`). `0` = все скрипты в файлы.

`ScriptExt` и `InlineLines` можно менять в окне настроек плагина.

## Формат `.bridge`

Одна строка — один объект:

```
Part "Floor" Anchored Size=40,1,40 CFrame=0,0,0 Color=#3A3A3A Material=Concrete #"Ground" $Zone="A" {
  PointLight "Glow" Brightness=2 Color=#FFCC88
}
Script "Spawner" @src="Scripts/ServerScriptService/Spawner.luau"
Script "Hello" @code="print('hi')"
```

Основное:
- `Класс "Имя"`, затем свойства, `#"Тег"`, `$Атрибут=Значение`, вложенность в `{ }`.
- Значения по умолчанию не пишутся, `true` пишется голым флагом.
- Числа, Enum, Vector3 (`1,2,3`), Color3 (`#RRGGBB`), UDim2, CFrame (`x,y,z` или `x,y,z|rx,ry,rz` в градусах) пишутся без кавычек.
- Скрипты: длинные лежат в файле (`@src`), короткие остаются прямо в `.bridge` (`@code`). Пути (`@src`, префабы) можно писать относительными и полными, Pull сохраняет путь как написан. Файл вне проекта работает, но Push предупредит и через git он не передаётся.
- Ссылки между объектами: `Part0=@"Workspace/Door/Frame"` или через id: `$_id="frame1"` и `@"*frame1"`.
- Пути объектов: имена через `/`, одинаковые братья `~2`, символ `/` в имени как `%2F`.
- Префабы: `$_prefab="Prefabs/Lamp.bridge"`, параметры — атрибуты корня префаба, подстановка `${Имя}`.
- Юнионы: `$_geo="<хеш>"` указывает на `Geometry/<хеш>.bin`.

Подробное описание для ИИ лежит в `AGENTS.md` в корне проекта.

## Префабы

Префаб — `.bridge`-файл с одним корневым объектом. Лежать он может где угодно: в `Prefabs/`, в `../Shared/…` или по полному пути (вне проекта git его не увидит).

```
# Prefabs/Turret.bridge
Model "Turret" $Damage=10 $Label="Турель" {
  Script "Logic" @src="Turret/Logic.luau"
}

# Scene/Workspace.bridge
Model "T1" $_prefab="Prefabs/Turret.bridge" $Damage=25 $Label="Левая"
```

- Подстановка только `${Имя}`: в свойствах и в коде скриптов. Старый `{Имя}` не подставляется, Push покажет подсказку.
- В коде подставляется литерал по типу параметра (строка в кавычках, число как есть, `#RRGGBB` → `Color3.fromRGB`, 2/3/4 числа → `Vector2/Vector3/UDim2.new`). `${Имя:raw}` — без кавычек, `$${` даёт `${`.
- Неизвестный параметр останавливает Push с ошибкой.
- `@src` внутри префаба считается от папки префаба.

## Террейн

Воксели сохраняются в `Terrain.voxels` (бинарный формат, git-diff для него бессмыслен). Pull/Push террейна идёт отдельно от обычной синхронизации. Область задаётся в карточке «Террейн» в плагине (рамку области можно показать в сцене).

Те же четыре действия есть и в приложении (карточка «Террейн»): **Studio → файл**, **Файл → Studio** (только предпросмотр), **Применить террейн**, **Отменить террейн**. Результат показывается в поле статуса и во вкладке «Изменения». Кнопки «Применить» и «Отменить» появляются, когда они возможны.

- Максимум 40000 кусков (по 64 вокселя).
- Push террейна всегда ручной: сначала предпросмотр, потом «Применить». Автоприменения нет.
- Отмена хранится только в памяти плагина.
- Перед применением сохрани плейс.
- `MaterialColors` не сохраняются.

## Юнионы

Форма юниона берётся через `SerializationService` и хранится по хешу, одинаковые юнионы делят один файл. Файлы `Geometry/*.bin` нужно коммитить вместе с `.bridge`.

- Создать новую геометрию из текста нельзя: сначала делается в Studio, потом Pull.
- Замена формы у существующего юниона пересоздаёт объект и сбивает ссылки на него.
- После обновления Studio формат сериализации может измениться: Push покажет изменение `$_geo` у всех юнионов, достаточно сделать Pull.

## Правила безопасности

- **Коммить в git перед Pull.** Страховки в виде `.bridge-prev/` пока нет.
- Не делай Pull, пока не применён Push.
- «Отменить» откатывает только ближайшее применение.
- Во время Play синхронизация заблокирована.
- Перед применением террейна сохрани плейс.
- Делай копию плагина перед его правкой.

## Известные ограничения

- Режим Merge есть, режима Replace нет.
- Атрибуты-ссылки и атрибуты типов Font/Sequence не поддерживаются.
- Сервисы нельзя создать через `Instance.new`, поэтому у них нет дефолтов и нельзя «вернуть к умолчанию».
- Объект (поддерево в одном файле) больше ~500 КБ не пройдёт.
- Префабы: повороты экземпляров, вложенные префабы и `@file` внутри префаба не поддерживаются. Префабы и скрипты по путям вне проекта не переносятся на другой компьютер через git.
- Если в Studio вручную изменить скрипт экземпляра префаба, Pull запишет его как собственный код экземпляра, а Push перезапишет правку шаблоном.
- Старые `.lua` не переименовываются при смене `ScriptExt`; два объекта не могут делить один файл скрипта.
- Файл сцены с отступами табами не разбирается.
- `WorldPivot` у Model пока не синхронизируется.
- Настройки игры (иконка, описание и т.п.) через Open Cloud запланированы, но не реализованы.

## Планы

- Порог удаления в приложении (сейчас только в Push плагина).
- Настройки игры через Open Cloud.
- Страховка `.bridge-prev/`, валидация формата, режим Replace.
